# v0.4.2 — Main conversations only

The bridge is now documented as a tool for main conversations. Subagents are told not to call it, so a spawned child task no longer stands in for its parent conversation. This release responds to the report in [#6](https://github.com/KeeVeeG/codex-claude-desktop-bridge/pull/6) without restricting which Codex tasks Claude can message first.

## Changes

- **Main conversations only:** the bridge skill states that only a main conversation uses the bridge. A Codex subagent or a Claude Code subagent must not call any bridge tool, including discovery, `bridge_status`, and the send tools. It returns its finding, the intended recipient, and the proposed message to its parent conversation, which decides whether to send it.
- The rule appears in the skill description and in the MCP server instructions, so agents see it alongside the bridge tools even when the full skill is not loaded.
- Routing, identity checks, and transports are unchanged. Claude can still start a conversation with any Codex task it discovers.

## Validation

- Final local Windows release validation passed 430 tests, with 4 macOS-specific tests skipped and no failures.
- Manifest alignment and package generation checks pass.

## Requirements and limitations

- Node.js 20 or later is required.
- The subagent rule is an instruction to agents, not an enforced check. A subagent that ignores it can still call the bridge.
- Claude may hold or refuse inbound messages under its own policy. A transport receipt is not a model-read or completion receipt.

## Updating

Update the plugin through its marketplace or install the native package with the included installer. In Claude CLI, run `/reload-plugins` and check `/mcp`; if old tools remain, exit and resume the exact session. Start a new Claude Code session in VS Code to load the new MCP process. Fully quit and reopen Claude Desktop when convenient. Start a new Codex Desktop task or restart the application, and restart terminal Codex sessions to load the new MCP process.
