# v0.4.1 — Claude Code in VS Code

Claude Code sessions running in VS Code can now exchange messages with Codex. This release integrates [#5](https://github.com/KeeVeeG/codex-claude-desktop-bridge/pull/5) and completes the related documentation and panel labels.

## Changes

- **Claude Code in VS Code:** sessions that register with `entrypoint: claude-vscode` appear in `list_claude_sessions`, are addressable by exact session ID, and can send to Codex. Earlier versions filtered them out of discovery. They use the same local inbox, identity checks, and trust boundary as CLI and Desktop Code sessions.
- Codex notices name these senders as `Claude Code VS Code`, and the conversation panel labels them `Claude VS Code`. The panel resource URI changes so hosts load the updated panel.
- The README and the bridge skill list the new entrypoint.

## Validation

- Windows and macOS CI cover Node.js 20, 22, 24, and 26, including package generation.
- Final local Windows release validation passed 430 tests, with 4 macOS-specific tests skipped and no failures.
- The contributor reported successful two-way messaging between Claude Code in VS Code and Codex on Windows.

## Requirements and limitations

- Node.js 20 or later is required.
- A Claude Code session in VS Code is reachable only while its session process is running, like other Claude sessions.
- macOS discovery accepts the same entrypoint, but messaging with a VS Code session on macOS has not been verified live.
- Claude may hold or refuse inbound messages under its own policy. A transport receipt is not a model-read or completion receipt.

## Updating

Update the plugin through its marketplace or install the native package with the included installer. In Claude CLI, run `/reload-plugins` and check `/mcp`; if old tools remain, exit and resume the exact session. Start a new Claude Code session in VS Code to load the new MCP process. Fully quit and reopen Claude Desktop when convenient. Start a new Codex Desktop task or restart the application, and restart terminal Codex sessions to load the new MCP process.
