# v0.4.0 — Terminal peers and macOS SSH delivery

The bridge now connects terminal conversations alongside Desktop conversations, with an optional SSH delivery route for macOS. This release integrates [#3](https://github.com/KeeVeeG/codex-claude-desktop-bridge/pull/3) and [#2](https://github.com/KeeVeeG/codex-claude-desktop-bridge/pull/2), plus the compatibility and reliability fixes reviewed in [#4](https://github.com/KeeVeeG/codex-claude-desktop-bridge/pull/4).

## New capabilities

- **Claude Code CLI on Windows:** discover and address interactive CLI sessions and running `sdk-cli` print-mode sessions, including `claude -p`. The conversation panel distinguishes CLI and Desktop recipients. Claude Desktop is not required for CLI messaging.
- **Codex terminal conversations:** discover recently updated conversations through the local daemon, send to loaded idle conversations, and steer active turns. Explicit terminal delivery can use `codex queue` for unloaded conversations. Queued messages wait for the selected conversation; submission does not mean the model has read them.
- **Explicit Codex transport selection:** `send_to_codex` accepts `auto`, `desktop`, `terminal`, and `ssh`. Conversations resumed in a different client are no longer routed by the client that originally created them. Ambiguous unloaded local targets require an explicit choice.
- **macOS support with a configured SSH host:** local Claude Code inboxes use validated Unix sockets. Outbound Codex delivery uses the operator-selected `CODEX_CLAUDE_BRIDGE_SSH_HOST` alias and an already-loaded, idle conversation on that host. The configured route stays on that host, uses strict SSH host-key checking, and never falls back to a local conversation with the same ID.

## Reliability and compatibility

- Recheck the selected Claude process, session, entrypoint, socket, and inbox key before writing. Reject identity changes detected immediately before delivery, including changes caused by `/clear`, resume, or process replacement.
- Require exact UUIDs for Codex queue delivery and normalize their casing before deduplication. Queue titles and aliases cannot select a different conversation.
- Scope remote delivery history and message IDs by SSH host. A remote conversation with a matching UUID does not appear as a local panel delivery.
- Keep SSH delivery limited to loaded idle targets without resuming closed conversations or reading their full history.
- Preserve uncertain delivery after transport loss or cancellation, expose it in MCP error text, and prevent automatic retransmission with the same message ID.
- Validate macOS process creation identity and Unix socket byte limits, and recover state locks safely after PID reuse.
- Preserve the v0.3.3 `from-mode="bypass"` compatibility fix for [issue #1](https://github.com/KeeVeeG/codex-claude-desktop-bridge/issues/1). Runtime delivery does not change the receiving Claude session's permission mode or inbound rules.
- Report the installed package version consistently in MCP, daemon, and SSH client initialization.

## Validation

- Three independent review rounds for each integrated PR; the final rounds had no actionable findings.
- Windows and macOS CI cover Node.js 20, 22, 24, and 26, including package generation.
- Final local Windows release validation passed 429 tests, with 4 macOS-specific tests skipped and no failures.
- Native, marketplace, and portable packages use synchronized manifests and are published with SHA-256 checksums.

## Requirements and limitations

- Node.js 20 or later is required.
- A Claude inbox is reachable only while its session process is running, including print-mode sessions.
- macOS requires an existing authenticated SSH alias, Codex CLI on that host, and a loaded idle target. The bridge does not provision SSH, start a daemon, or reopen a closed target.
- The combined macOS SSH implementation has automated and static validation, but has not had a new live end-to-end exchange between the installed Claude and Codex applications. Linux and WSL delivery remain unsupported.
- Claude may hold or refuse inbound messages under its own policy. A transport receipt is not a model-read or completion receipt.

## Updating

Update the plugin through its marketplace or install the native package with the included installer. In Claude CLI, run `/reload-plugins` and check `/mcp`; if old tools remain, exit and resume the exact session. Fully quit and reopen Claude Desktop when convenient. Start a new Codex Desktop task or restart the application, and restart terminal Codex sessions to load the new MCP process.
